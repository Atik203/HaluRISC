## 2. Freeze and Verify

```powershell
# Rebuild the manifest from current artifacts (hashes, seeds, hardware, env)
& .venv\Scripts\python.exe src\models\make_manifest.py

# Verify every reported artifact loads and predicts (prints ALL ARTIFACTS VERIFIED)
& .venv\Scripts\python.exe src\models\verify_artifacts.py
```

- `make_manifest.py` writes `artifacts/results/manifest.json` with split
  integrity, dataset hashes, per-phase artifact hashes, package versions,
  hardware, `HALU_*` settings, and (on Colab) a source fingerprint.
  `docs/manifest.frozen.json` is the frozen copy used by the papers.
- `verify_artifacts.py` loads B2 boosters, B4 calibrators, B3/B4 prediction
  schemas, and B5 reports. FaithBench text is checked to never appear in shipped
  error-case artifacts (CC BY-NC-SA).
- Rule: any number that appears in a paper must be traceable to an artifact that
  this gate verifies.

## 4. One-Command and Per-Phase Protocol

```powershell
# Inspect the exact commands without executing anything
& .venv\Scripts\python.exe src\models\run_all_experiments.py --dry-run

# Full chain: downloads → B1 unified → features → B2 → B3 → B4 → B5 → manifest → verify
& .venv\Scripts\python.exe src\models\run_all_experiments.py --device cpu

# Resume after a crash / run a subset
& .venv\Scripts\python.exe src\models\run_all_experiments.py --from b3 --to b5 --keep-going
```

- Config: `configs/version_b.yaml` (the run-all config; its filename is a
  historical identifier and is referenced by the code).
- Each phase subprocess-invokes its own runner (`run_b2_baselines.py`,
  `run_b3_cross_domain.py`, `run_b4_calibration_shift.py`,
  `run_b5_explanation_reliability.py`), so the runners remain the single source
  of truth.
- Every execution writes `artifacts/results/run_all_report.json` (resolved
  arguments, per-phase status/duration, git commit).
- Individual runners can be called directly, e.g.
  `python src/models/run_b2_baselines.py --device cpu` or
  `python src/models/analyze_length_shortcut.py` (length-binned analysis, CPU,
  seconds).

## 5. Colab Regeneration Path

`colab/HaluRISC_Training_Version_B.ipynb` is self-contained: cell 3 embeds the
runtime source tree, writes it to `/content/HaluRISC/`, and verifies SHA-256
hashes before execution. Upload only the notebook (no source zip).

1. Open the notebook, choose **GPU → L4** when available.
2. Run cells 1–5, then 5b, then the phase cells (6/6b features, 7d B2–B4, B5).
   Heavy phases checkpoint to `Drive/halurisc_cache/`; restore cells
   (`7b.0`, `7d.5`, `7d.6`, `7g.0`) resume a crashed session without redoing
   finished phases.
3. Cell 35 packages `halurisc_artifacts_<date>.zip` to Drive. Download and unzip
   **at the repo root**; the API and dashboard then load the real artifacts.
4. After any source change, regenerate the notebook with
   `python colab/build_self_contained.py` and re-upload.

All cached artifacts are CPU-portable: XGBoost is trained with
`HALU_XGB_DEVICE=cpu` and B4 calibrators are pure sklearn.

## 6. Docker Path

```powershell
docker build -t halurisc-api .
docker run --rm -p 8000:8000 halurisc-api
curl http://127.0.0.1:8000/health
```

Single-stage image (`python:3.12-slim` + pinned requirements + `src/` +
`artifacts/`), `libgomp1` for XGBoost's OpenMP runtime, one uvicorn worker, no
`--reload`, healthcheck on `/health`. The image is intentionally CPU-only; CUDA
remains an optional host-side acceleration (`HALU_API_DEVICE=cuda`).
`.dockerignore` keeps the image secret-free (no `.env`, no `data/raw`, no
`web/node_modules`).

## 8. Known Failure Modes and Fixes

| Symptom | Cause | Fix |
|---|---|---|
| Booster fails to load with "input stream corrupted" | Colab booster saved with a different XGBoost version | Keep `xgboost==3.3.0` everywhere; do not bump to 3.4.0 |
| `pip install -r requirements.txt` fails on `en-core-web-sm` | spaCy models are not published on PyPI | The pin uses the official GitHub release wheel URL; do not replace it with a bare version pin |
| `uv` resolution conflicts on `requests` | PyTorch extra index shadows PyPI packages | Add `--index-strategy unsafe-best-match` (pip does not need it) |
| API refuses GPU | torch built without CUDA or driver mismatch | `HALU_API_DEVICE=cuda` auto-falls back to CPU; check `torch.cuda.is_available()` |
| First API request is slow | heavy models load lazily | Set `HALU_API_PRELOAD=1` (default) so spaCy/NLI/SBERT preload at startup |
| CUDA OOM on the 6 GB laptop | concurrent extraction | One worker, inference lock, fp16; close other GPU apps |
| FaithBench text appears in an artifact | license violation (CC BY-NC-SA) | Raw text must never ship; `verify_artifacts.py` enforces redaction |

## 11. Anticipated Defense Q&A

### Validity and leakage

**Q: F1 = 0.9846 looks too high. Is something leaking?**
No. The split is grouped by `item_idx` so both answer variants of a question
stay in one partition, and an automated check proves zero cross-partition
groups. Leakage was found and removed: the invalid row-level split gave 0.9886,
the grouped split gives 0.9846. Artifact controls (answer-only TF-IDF 0.9224,
heuristic 0.9352) show why the benchmark is easy, and we report that openly.

**Q: Why is the overlap heuristic so strong?**
Because HaluEval's hallucinated answers are generated to be plausible but often
reduce lexical overlap with the reference. That is a known benchmark artifact,
which is exactly why heuristic and TF-IDF controls exist and why we frame
results as HaluEval performance, not general detection quality.

**Q: Why group by `item_idx` or `source_id`?**
Both answer variants of one question share its context, and one RAGTruth source
elicits multiple responses. Without grouping, the model can memorize the pairing
instead of learning evidence consistency.

### Method choices

**Q: Why XGBoost instead of a transformer classifier?**
It matched or beat every baseline while staying CPU-fast, giving tree-exact SHAP
values and a 0.82 MB artifact. The neural route needs GPUs, resists
interpretation, and costs more; the LLM judge we measured is 100x more
expensive and scores lower F1 on the same samples.

**Q: Why these 26 features?**
Each group was ablated across three seeds. Lexical grounding dominates, length
and NLI contribute, and the entity/numeric/hedging groups are neutral but cheap
and interpretable; the semantic group is mildly harmful and disclosed. We report
all of these deltas rather than tuning the story.

**Q: Is the NLI model not redundant with lexical overlap?**
No. NLI-only reaches F1 0.6714, and removing NLI costs 0.0023 F1, but its main
value is explanation: contradiction probability is the signal users can check
against the quoted evidence sentence.

### Calibration

**Q: Your calibration experiment says calibration does not help. Why include it?**
That is the honest result on the source domain: XGBoost is already calibrated
(ECE 0.0045) and Platt/isotonic make it worse. The point of the experiment is
that calibration pays off exactly where it is needed: after a domain shift.

**Q: What does the 0.81 → 0.13 result prove?**
It proves the miscalibration out of domain is a domain-shift problem, not a
fitting-method problem: a calibrator fitted on HaluEval barely changes the ECE,
while re-fitting on 5,034 RAGTruth rows cuts it to 0.13 and the Brier score from
0.80 to 0.16.

**Q: Why must the threshold be retuned?**
After target recalibration the predicted positive rate collapses at the fixed
0.5 threshold. The probabilities are fixed; the labels only follow after
threshold retuning, and we state that as a deployment caveat.

**Q: Why is the chat score different from the model score?**
The raw HaluEval-Platt score saturates on full sentences. The display score uses
an evidence-domain isotonic calibrator fitted on natural RAGTruth rows, adjusted
by per-claim verdicts. The raw model score remains visible as `legacy_score`.

### Transfer

**Q: Why does zero-shot transfer fail?**
The measured mechanism is the answer-length confound: in HaluEval the
hallucinated share rises from 2.1% (one word) to 99.2% (17+ words), and the
model learned length as a proxy for the label. Natural responses are full
sentences, so recall is 1.0 and AUROC is near chance. We report this as the
central negative result.

**Q: What would fix the transfer gap?**
Three options, all out of scope for this study: domain-aware recalibration
(already demonstrated), per-claim verification against retrieved evidence
(implemented in the deployed system), and training on natural corpora such as
RAGTruth, which would change the “benchmark-trained detector” framing.

### Explanations and the audit

**Q: How do you know SHAP explanations are not decorative?**
They were triangulated (Kendall τ = 0.66 against permutation importance),
bootstrapped (top-5 set identical across 1,000 resamples), neutralized
(monotone score drop to −0.412 at k = 10), and perturbed (content edits move the
score, neutral edits do not, top-1 never flips).

**Q: The B5.5 audit was done with an AI assistant. Is that valid?**
It is a structured expert audit, not a human-subject study, and we say so: the
sheet records `review_mode = ai-expert`, the two passes and their agreement are
reported, and the sampling caveat is stated. It is used as error analysis, never
as a human plausibility rate.

**Q: Why did the audit mark 15 of 26 cases implausible?**
Because the sheet was deliberately built from false positives, false negatives,
and borderline scores; it is error-enriched by design. The rate describes the
audit sample, not the test set. The qualitative finding is what matters: FPs
inherit the length confound and FNs reuse context entities.

### Ethics and limits

**Q: Could the system create false trust?**
It predicts risk, not truth, and the interface never claims otherwise: scores
are labelled risk estimates, a training-data warning accompanies every
prediction, and the known failure modes (out-of-domain miscalibration, length
sensitivity, English-only data) are documented in the papers.

**Q: What are the biggest limitations to state up front?**
Synthetic training data, binary labels, English-only features, one training
dataset, benchmark label noise, and the length confound. Every one is quantified
in the Results or Limitations sections.

### System

**Q: What is the real latency and cost?**
61.8 ms median per analysis on the reference laptop, about $0.001 per 1,000
local predictions, versus 1,310 ms and $0.105 per 1,000 for the measured LLM
judge.

**Q: Is the API key safe?**
Yes. The OpenAI key lives only in server-side environment files; the Next.js
layer proxies ML calls and streams chat, so the key never reaches the browser.
`.env` files are gitignored and never committed.

**Q: Does the demo work without an API key?**
Yes. `/demo` is rendered offline from artifacts, and `/analyze` works without
OpenAI. Only chat and the LLM judge need the key.

### Reproducibility

**Q: Can the numbers be reproduced from a clean clone?**
Yes: install the pinned requirements, run the download/prepare scripts, then
`run_all_experiments.py` and `verify_artifacts.py` (prints
`ALL ARTIFACTS VERIFIED`). The Colab notebook reproduces the heavy run and
brings the artifacts back.

**Q: What exactly is frozen?**
`docs/manifest.frozen.json` plus the artifact hashes, split indices, dataset
revisions and SHA-256 hashes, seeds, package versions, and hardware. Every
number in the manuscript traces to a file covered by that manifest.

## 12. Do-Not-Say List

1. Do not claim **state-of-the-art** or a guaranteed journal quartile.
2. Do not say the system detects **truth**; it predicts evidence-consistency
   risk.
3. Do not call the HaluEval result **general hallucination detection**.
4. Do not describe the B5.5 audit as a **two-human-reviewer study**.
5. Do not claim to be the **first to use SHAP** for hallucination detection.
6. Do not present the audited plausibility rate as a **test-set estimate**.
7. Do not claim the raw score is trustworthy out of domain: the transfer result
   says the opposite.
8. Do not omit the sampling caveat, the license restrictions (FaithBench), or
   the model's English-only scope.

## 14. Glossary

| Term | Meaning |
|---|---|
| **HaluRISC** | Hallucination Risk Scoring and Calibration, this project |
| **Hallucination** | Fluent text that is unsupported by or contradicts the available evidence |
| **HaluEval QA** | The training/in-domain benchmark (10,000 questions, paired correct and hallucinated answers) |
| **RAGTruth** | Naturally generated RAG responses with human span annotations; the external test corpus |
| **FaithBench** | Summarization hallucination stress test from modern LLMs (CC BY-NC-SA) |
| **Item group** | `item_idx` in HaluEval; both answer variants of one question |
| **Source group** | `source_id` in RAGTruth; one source can elicit multiple responses |
| **Grouped split** | Train/val/test split that keeps a whole group in one partition, preventing leakage |
| **Leakage** | Test information sneaking into training, e.g. the paired answer variant |
| **Shortcut / artifact control** | A baseline (answer-only TF-IDF, overlap) that exposes benchmark surface patterns |
| **Feature group** | One of the seven families of engineered features (length, lexical, entity, NLI, numeric, hedging, semantic) |
| **NLI** | Natural Language Inference: entailment / contradiction / neutral classification |
| **SHAP** | Shapley-value feature attribution for model predictions (TreeExplainer for XGBoost) |
| **Platt scaling** | Sigmoid calibration fitted to map scores to probabilities |
| **Isotonic regression** | Monotone step-function calibration |
| **ECE** | Expected Calibration Error, the gap between predicted probabilities and observed frequencies |
| **Brier score** | Mean squared error of probabilistic predictions (lower is better) |
| **NLL** | Negative log-likelihood of the predictions |
| **MCC** | Matthews correlation coefficient, balanced even for imbalanced classes |
| **PR-AUC** | Area under the precision-recall curve; informative under class imbalance |
| **AUROC** | Area under the ROC curve; overall ranking quality |
| **McNemar's test** | Paired test for comparing two classifiers on the same samples |
| **Bootstrap CI** | Confidence interval from resampling with replacement (1,000 resamples here) |
| **Wilcoxon signed-rank** | Non-parametric paired test used across the three seeds |
| **Ablation** | Removing a component (here, a feature group) and retraining to measure its contribution |
| **Neutralization** | Setting top SHAP features to their median to test whether they drive predictions |
| **Perturbation stability** | Editing answer text and checking that semantic edits move the score while neutral edits do not |
| **Display score** | Evidence-domain calibrated score shown to users (isotonic on RAGTruth + per-claim adjustment) |
| **Legacy score** | HaluEval-Platt source-domain score kept as a labelled secondary signal |
| **Tier 1–4** | Verification layers: risk card, per-claim NLI, retrieval, LLM-judge routing |
| **BFF** | Backend-for-frontend: the Next.js layer that proxies API calls and hides server keys |
| **fp16** | Half-precision inference used on the 6 GB GPU to fit the NLI/SBERT models |
| **Manifest** | Frozen JSON recording artifact hashes, seeds, versions, hardware, and provenance |
