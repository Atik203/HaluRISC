# Methodology and Reproducibility Review — `02_method.md`

## Verdict

**Major revision required. The offline protocol is largely reproducible, but the manuscript is not reproducible as a deployed system.**

The method description, feature accounting, grouped tuning, official splits, and disjoint-conformal check are mostly sound. The blocking problems are: (i) the FastAPI serving path omits the log1p transform that the EC-XGB model was trained and calibrated on; (ii) the manuscript conflates the tuned m3, fixed-hp m3, B2, and B6 m0 checkpoints across the abstract, tables, and deployment claims; (iii) the claim-feature verdict rule omits the relevance gate that the code applies; and (iv) Algorithm 2 does not specify the exact training rows, per-seed tuning, early stopping, or test-row protections. These are fixable, but they must be fixed before the deployment and reproducibility claims are credible.

The 14 requested checks were completed. Four issues are blocking (I-01 to I-04); checks 3, 4, 8, and 12 are partial, check 5 is correct in the manuscript and training but fails at serving, and checks 13 and 14 fail. The remaining issues are medium or minor.

## Top 3 fixes

1. **Fix the serving feature transform and prove parity (I-01).** Add `log1p` for `n_chars` and `n_words` in every EC-XGB path (`/predict`, `/predict/compare`, `/explain`), keep raw values for B2, add a regression test that compares the API matrix with `run_b6_modified.feature_matrix(..., log_lengths=True)`, and regenerate Figure 3 and all deployed screenshots. This is a hard blocker: until it is fixed, the paper’s deployment claims and the 0.999/35.4% example are not reproducible.

2. **Make checkpoint identity explicit and consistent (I-02).** Define B2, B6 m0, m3-tuned, and m3-fixed in one place, label every table/figure/caption, and decide which one is deployed. If the deployed model is m3-tuned (as the API currently loads), quote m3-tuned in the abstract and conclusion; if the intended deployment is fixed-hp, load the fixed-hp artifact and say so. Distinguish B2 from B6 m0 everywhere, including the “conventional” rows in `tab:models`, `tab:ec`, `tab:shift`, and `tab:external`.

3. **Complete the claim-feature and Algorithm 2 specifications (I-03, I-04).** Add the relevance-gate constants and the pre-gate/post-gate distinction to §3.3; state that the six-claim cap is for the feature block (or align `/verify` to six); and rewrite Algorithm 2 with the exact 14,000 + 10,056 training rows, per-seed 30-configuration tuning, 30-round early stopping on 3,000 validation rows, 5,034 calibration rows, 3,000 HaluEval test and 900 QA test rows untouched, and both threshold rules. This is what makes the method reproducible from the paper rather than only from the repository.
